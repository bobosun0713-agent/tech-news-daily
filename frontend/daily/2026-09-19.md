## 📑 焦點摘要
- 即時串流更新不該直接打進 setState；先緩衝再按幀刷新。
- 把 in-app announcement 從頁面硬編碼，移到可規則化的 slot。
- 重連不是布林值；把連線狀態、心跳與補資料流程拆開。
- 用 CRDT + P2P 取代中央協調器，減少後端壓力與同步成本。
- 自動化遷移要先判定 client/server 邊界，不然容易引爆 hydration 問題。

## 深入閱讀

### 1. [React WebSocket 效能：用 RAF 緩衝把串流更新壓回幀率內 (React WebSocket Performance: RAF Buffering Pattern)](https://dev.to/nainikmehta/react-websocket-performance-raf-buffering-pattern-1ien)
* **核心重點：** 先在 React 外部緩衝訊息，再用 RAF 合併 flush，避免每則訊息都觸發重新渲染。
* **相關標籤：** `#React` `#WebSocket` `#Performance`

### 2. [不要把 Banner/modal 硬寫進 Next.js：改用規則式 Experience Slot (Stop hardcoding <Banner /> modals in your Next.js codebase)](https://dev.to/pavan_s_poojary/stop-hardcoding-modals-in-your-nextjs-codebase-c08)
* **核心重點：** 公告與導流內容應由 runtime 規則決定，避免 bundle 膨脹、hydration mismatch 與部署阻力。
* **相關標籤：** `#Nextjs` `#UIArchitecture` `#Hydration`

### 3. [React/Node WebSocket 重連狀態機：把斷線、重試與心跳拆清楚 (A WebSocket reconnect state machine for React and Node)](https://dev.to/yaseenyk04/a-websocket-reconnect-state-machine-for-react-and-node-4nb5)

* **相關標籤：** `#WebSocket` `#StateMachine` `#Realtime`

### 4. [零後端 P2P 協作編輯：React 結合 Yjs 與 WebRTC (Building a Zero-Backend P2P Live Collaboration System in React with Yjs and WebRTC)](https://dev.to/pyaephyomaungdev/building-a-zero-backend-p2p-live-collaboration-system-in-react-with-yjs-and-webrtc-3ijb)

* **相關標籤：** `#Yjs` `#WebRTC` `#Collaboration`

### 5. [自動 migration 工具別亂插 `use client`：Client boundary 要明確 ('use client' Injection: Why Automated Migration Tools Need It (And When They Get It Wrong))](https://dev.to/digitaldev/use-client-injection-why-automated-migration-tools-need-it-and-when-they-get-it-wrong-435c)
